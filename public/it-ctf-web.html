🛡️ CTF Bảo mật Web — SQLi · XSS · Path Traversal · Command Injection

0/4 cờ

Mục tiêu

Đây là môi trường sandbox an toàn mô phỏng 4 lỗ hổng bảo mật web phổ biến nhất theo OWASP Top 10. Bạn sẽ đóng vai pentester (kẻ tấn công đạo đức) — tìm input để khai thác lỗ hổng, hiểu cách lỗ hổng phát sinh, và đọc bài học để biết cách phòng thủ ở đời thật.

Mỗi thử thách hiện code dễ tổn thương → bạn nhập payload → hệ thống đánh giá cục bộ. Không có server thật bị tấn công.

⚠️ Kiến thức này chỉ dùng để bảo vệ. Việc tấn công hệ thống không được phép là vi phạm pháp luật (Bộ luật Hình sự 2015 — Điều 287, 289).
1 Login bypass qua SQL Injection SQLi ▶

Hệ thống cũ ghép chuỗi SQL trực tiếp từ form đăng nhập — không hề parameter hoá:

// Backend (PHP/Node giả lập) const sql = `SELECT * FROM users WHERE name='${u}' AND pass='${p}'`; if (db.query(sql).rows.length) login();

Có 1 tài khoản tên admin trong CSDL. Bạn không biết mật khẩu — hãy nhập payload vào ô Tên sao cho query trả về ≥1 row (đăng nhập thành công) bất kể mật khẩu là gì.

💡 Bạn cần thoát khỏi dấu nháy đơn rồi nối điều kiện luôn đúng. Thử: admin' OR '1'='1 — phần sau dấu -- hoặc tương đương sẽ biến mật khẩu thành vô nghĩa.
📚 Bài học phòng thủ

• Parameter hoá / Prepared statements — không bao giờ ghép chuỗi vào câu SQL. Dùng db.query('SELECT * FROM users WHERE name=? AND pass=?', [u, p]). ORM (Prisma, Sequelize, Drizzle) tự làm việc này.
• Hash mật khẩu với bcrypt/scrypt/argon2 — không lưu plain text.
• Least privilege — user DB chỉ có quyền cần thiết.
• WAF + rate limit chặn brute-force/automated payloads.

2 Reflected XSS — chiếm DOM XSS ▶

Trang tìm kiếm render thẳng query vào HTML:

// Trang /search?q=... results.innerHTML = `Bạn tìm: ${req.query.q}`;

Hãy nhập payload sao cho code JavaScript tự thi hành trên trang — cụ thể: gán window.__pwn = 1 để chứng minh control flow.

💡 Thẻ <script> được set qua innerHTML KHÔNG chạy (trình duyệt cố tình chặn). Thử event handler trên thẻ hợp lệ: <img src=x onerror="window.__pwn=1">
📚 Bài học phòng thủ

• Output encoding — luôn escape < > " ' & khi đưa user input vào HTML. Template engine (EJS, Handlebars, JSX) tự escape {{var}}; CHỈ dùng raw {{{var}}} khi đã sanitize.
• Content Security Policy (CSP) — header script-src 'self' chặn inline script.
• HttpOnly cookies — JS không đọc được session cookie nếu attacker chiếm được DOM.
• Sanitize HTML bằng DOMPurify khi BUỘC phải render HTML do user soạn.

3 Path Traversal — đọc file bí mật LFI ▶

Endpoint /download?f=... ghép tham số trực tiếp vào đường dẫn:

// Backend const p = `./public/uploads/${req.query.f}`; res.sendFile(path.resolve(p));

File hệ thống /etc/passwd (Linux) đang ngoài thư mục public. Hãy đặt giá trị f để đọc được file đó.

💡 Mỗi ../ đi lên 1 cấp. Tính từ ./public/uploads/ cần 3 cấp để ra root, rồi etc/passwd. Đáp án: ../../../etc/passwd
📚 Bài học phòng thủ

• Whitelist tên file hoặc map id → tên (vd /download?id=42 tra DB).
• Normalize + validate: path.resolve(p).startsWith(SAFE_DIR) để chặn ra ngoài.
• Block các pattern: .., %2e%2e, byte null.
• Chroot / container — process không có quyền đọc /etc ngay từ đầu.

4 Command Injection — thoát khỏi tham số RCE ▶

Endpoint /ping?ip=... ghép input vào lệnh shell:

// Backend exec(`ping -c 2 ${req.query.ip}`, callback);

Mục tiêu: nhập ip sao cho shell chạy thêm lệnh whoami sau lệnh ping (để xác định mình là user nào).

💡 Shell có nhiều ký tự chia lệnh: ; (chạy lần lượt), && (chạy nếu thành công), | (pipe), $(...) (command substitution). Thử: 8.8.8.8 ; whoami
📚 Bài học phòng thủ

• KHÔNG dùng shell khi không cần — dùng execFile('ping', ['-c', '2', ip]) (Node) hoặc thư viện chuyên dụng. Tham số không qua shell parsing.
• Validate strict: chỉ cho phép IPv4 hợp lệ với regex/parser, từ chối mọi ký tự khác.
• Least privilege + seccomp/AppArmor giới hạn syscall process được phép.
• Tuyệt đối tránh eval, exec, system với input chưa rửa.
